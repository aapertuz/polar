# Quick AI system surface

Status: Complete
Owner: Codex / project owner
Created: 2026-10-07

## Goal and acceptance criteria

Create a global Quick AI command surface that expands from the top island, using the supplied reference for the surface composition while preserving the existing Polar home interface. Deliver an interactive, deterministic UI preview with ephemeral state only.

### Explicit user requirements

- Clicking the main Polar icon at the left of the island invokes Quick AI.
- Cmd K invokes the same experience globally; Escape closes it.
- The island smoothly expands downward into a larger command surface. The existing workspace remains visible and subtly dimmed, with its layout, selected mission, tabs, timeline, and window positions preserved.
- Quick AI is a system layer, independent of the mission window, with no separate page or native window.
- Show POLAR identity, current context such as F1 Pilot, a prominent input with `Ask Polar or describe what you want to accomplish...`, visible context in use, and Context, Attach, and Sources actions.
- Support short commands and short responses inside this surface. For `Nick moved the event to Nov 22.`, show `I can update the deadline and adjust the execution plan. 3 actions will move.` and an `Apply change` action.
- Every New mission entry point opens the same surface with `What are you trying to accomplish?`.
- Keep a path to a future larger conversational mode, but do not implement that mode, its navigation, or a separate conversation window.
- Follow existing Polar tokens, typography, components, accessibility, and reduced-motion policies. Treat the reference as the Quick AI visual target; do not recreate its differing home content.

### Implementation acceptance scenarios

Once the scope decisions below are resolved, verify:

1. Icon, Cmd K, and New mission invoke one shared surface. Repeated invocation never stacks surfaces or resets an active draft unintentionally.
2. Opening and closing leave the home composition and mission state unchanged. The expanded surface sits above dragged windows and timeline drawers without moving them.
3. The normal entry displays the active mission as explicit, removable context. Context selected for the request is reflected in the visible chips; removing a chip excludes it from submission.
4. New mission uses the specified prompt and remains the same island surface.
5. Submit and the example response work inline, with an explicit Apply action. No change is represented as saved before a real commit or clearly identified preview outcome.
6. Keyboard focus enters the input, remains in the active surface and its context controls, and returns to the invoking control on close. Escape dismisses a nested picker first, then Quick AI. Typing, IME composition, and blank submission behave correctly.
7. The surface remains usable at the desktop review sizes in [Verification](../../VERIFICATION.md), with wrapping chips/actions, bounded internal scrolling, readable copy, and no horizontal overflow. Reduced motion removes spatial expansion.

## Decisions and discoveries

### Supported by the request and project references

- Use the existing top island as the visual origin and keep the mission workspace in place. Keep the compact status strip visible above the expanded command body, as in the reference, with both managed as one system layer.
- Present one dominant input, a concise context row, and a compact inline result. Do not add chat bubbles, avatars, a thread sidebar, a full transcript, model selectors, or duplicated mission overview data.
- Use near-black window tokens, Geist body text, existing system typography, thin dark borders, restrained shadow, and light primary buttons. Red remains reserved for attention. The prominent command input is a request-specific extension of the normal quiet input pattern.
- Preserve the existing 16px island corners when closed. Start the expanded body with the existing 22px window radius and 32px padding, adapting to narrower widths. Target approximately 900px width at 1672×941, centered beneath the status strip; clamp to available viewport space.
- Animate expansion from the top center over 220ms using the existing HOME_MOTION easing; fade the dimmer with it. Avoid a detached slide-in modal or scaling text. Reduced motion uses an opacity transition without geometry movement.

### Decisions — confirmed by the user on 2026-10-07

Delivery scope: **Interactive UI preview first**. Short responses, context selection, attachment metadata, and Apply results are deterministic and ephemeral, with clear preview labeling. Real AI, backend integration, uploads, persistence, saved mission changes, and larger conversational mode are outside this plan.

Confirmed UX decisions:

1. Cmd K invokes Quick AI anywhere in the focused Polar app, including while inputs and previews are active; it is not an OS-wide shortcut.
2. Normal command entry starts with the active mission as removable context. Mission evidence is offered as explicitly selectable sources; display-only fixture records are not represented as uploaded files.
3. New mission starts with no inherited mission or sources and uses its exact prompt. Command and New mission drafts are kept separately in session state.
4. Clicking the dimmed backdrop closes the surface. Reinvoking an open surface focuses its input. Nested selectors dismiss before the surface on Escape.
5. Apply confirms a clearly labeled simulated result inside Quick AI without modifying the home fixtures.
